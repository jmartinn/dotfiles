# Working preferences

- Prefer built-in tools and installed CLIs. Add skills or integrations only when
  the task needs them; keep project-specific tools and instructions in the project.
- Make the smallest useful change, follow repository conventions, and verify the
  resulting behavior with relevant checks. Preserve unrelated user changes.
- Do not bypass Git hooks. Use noninteractive Git commands. Commit messages use
  a lowercase conventional subject only, no body or AI attribution. Apply this
  convention to any agents you dispatch as well.
- Keep answers concise. Report the outcome, verification, and unresolved limits.

For long tasks, record decisions and next steps in a short project handoff before
compaction. Start a fresh session when switching tasks; read detailed reference
material only when needed.
